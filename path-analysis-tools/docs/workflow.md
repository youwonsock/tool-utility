# 호스트 중립 작업 절차

1. 작업 폴더를 만들고 원본 이미지와 SheetManifest를 보존합니다. 순서·유효 셀·누락 이미지 여부를 확인합니다.
2. read_frame으로 필요한 셀을 확대해 봅니다. 추적 카메라의 플레이어 화면 위치만으로 이동을 계산하지 않고 배경 랜드마크의 상대 이동과 행동을 읽습니다. 회전/배율/높이를 판단하기 어렵다면 note로 근거를 남깁니다.
3. 관측 상대 XYZ와 source ID를 ObservationSet에 기록합니다. 플레이어를 벗어난 카메라 구간은 excluded, 판단 불가 구간은 unresolved/null입니다. 알아보지 못한 구간을 창작해 이어 붙이지 않습니다.
4. calculate_path → preview_path를 실행합니다. 상단/측면에서 좌우 회전 순서, 행동 경계, 고저 변화와 끊긴 경로를 검토합니다. 경로는 초안이며 실제 3D 세계의 유일한 복원 결과를 의미하지 않습니다.
5. 사용 가능한 엔진 도구를 조회합니다. 실제 scene/scope/frame을 확인하고 snapshot을 수집합니다. 다른 프로젝트를 같은 대상으로 취급하지 않습니다.
6. 신규는 빈 선택 루트, 기존은 명시적으로 지정한 범위만 사용합니다. 기존의 이동 설정·이벤트·외부 참조는 유지합니다. 참조 소유를 증명하지 못한 점은 owned=false 또는 external_reference_count=null로 표시합니다. 관리하는 경로 배열 이외의 참조는 같은 루트 안에 있어도 이 수에 포함합니다.
7. 기존 점 ID를 재사용하고 모든 보존점을 보호합니다. bindings와 명시적 remove_point_ids로 기존 점을 분류합니다. 다른 좌표계는 사용자가 선택한 명시적 placement로 변환합니다.
8. plan_scene_edits → 최신 snapshot으로 verify_scene_apply. ready일 때 작업별 사전 조건과 depends_on을 확인하며 적용합니다. 생성 시 실제 객체 참조를 즉시 기록합니다.
9. 생성/이동 → 참조/순서 → 허용된 삭제 → Rebuild/저장·재조회 순서를 지킵니다. 실제 성공을 확인한 작업만 ApplyLog에 성공으로 기록합니다.
10. 부분 실패는 중단하고 실제 스냅샷을 새로 얻습니다. created_bindings와 기존 대응표를 합쳐 재계획합니다. 실패 전 생성한 객체를 다시 생성하지 않습니다.

작업 기록에는 이미지, manifest, 관측, 계획, 적용 전후 snapshot, bindings, EditPlan, ApplyLog와 검증 결과를 보관합니다. AI 키·엔진 인증 정보는 저장하지 않습니다. 각 호스트는 표준 MCP 이미지 반환 또는 CLI PNG 파일을 자신의 이미지 입력 기능으로 읽을 수 있어야 합니다.
