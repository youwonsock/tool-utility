# 운영·복구 계약

## 상태와 소유권

서비스는 localhost에만 바인딩하고 매 시작 시 발급한 bearer 암호를 사용자 데이터 파일에 저장합니다. 브라우저 Origin 요청은 받지 않습니다. 워커별 OpenCode 서버는 별도 임의 포트와 Basic 인증 암호를 사용합니다. 인증 값은 MCP 응답에 포함하지 않습니다.

서비스 소유자는 PID와 프로세스 생성 시각으로 확인합니다. 새 서비스는 살아 있는 소유자를 교체하지 않습니다. 죽은 소유자의 잠금만 단일 회수 절차로 정리합니다. 소유 기록이 없거나 손상되어 실행 여부를 확인할 수 없으면 중복 실행보다 중단을 선택합니다. 그런 경우 `service.log`, `jobs/<attempt>/launch.json`, `started.json`, `worker.json`을 확인해야 합니다. PID 숫자만으로 임의 프로세스를 종료하지 마세요.

상태 변경은 체크섬이 있는 append journal에 fsync한 뒤 원자적으로 snapshot을 교체합니다. 재시작 시 snapshot 이후의 완전한 journal 레코드를 복구합니다. 마지막 불완전 레코드는 제거하고 중간 레코드 손상은 오류로 처리합니다. 데이터 형식/프로토콜은 버전 1입니다.

모델 전송 전 실행·시도·세션·메시지 ID와 의도를 저장합니다. worker 시작은 독립적인 배타적 기록으로 보호합니다. prompt 응답 유실 시 동일 세션에서 해당 메시지를 찾으며 재전송하지 않습니다. 실제 사용자 메시지, 해당 메시지를 부모로 가진 완료 응답, pending tool 부재, idle 상태를 함께 확인합니다. 서버의 idle 상태만으로 성공을 판정하지 않습니다.

검증 셸 명령도 명령과 메시지 ID를 먼저 기록합니다. 응답 유실 시 같은 메시지의 실제 bash 결과를 찾습니다. 알 수 없는 종료 코드는 `unknown`이며 같은 명령을 자동 재실행하지 않습니다. 질문/권한 응답은 전송 의도와 결과를 별도로 기록하며 전달 불확실 상태에서 자동 반복하지 않습니다.

## 판단표

| 상황 | 동작 |
| --- | --- |
| Codex/MCP 연결 종료 | 서비스·워커 계속 실행; 재연결 후 `list_runs` |
| 서비스만 종료, 워커 생존 | 같은 워커 기록을 다시 관찰; 모델 요청을 새로 보내지 않음 |
| worker 종료, OpenCode 생존 | `orphaned`; 자원 잠금 유지; 기존 세션을 조회하고 명시적으로 취소 후 수정 결정 |
| 재부팅으로 이전 프로세스 소멸 | `interrupted`; 기존 요청 재전송 금지; Codex 수정 지시로 새 시도 |
| 시작 여부/프로세스 소유권 불명 | `orphaned`/`stop_uncertain`; 자원 재할당 금지 |
| 모델/검증 실패 | `needs_review`; Codex 지시 전 재시도 없음 |
| 범위·문맥 위반 | 결과 증거 보존, 승인 차단 |
| 통합 도중 서비스 종료 | 실제 HEAD·부모·diff를 대조; 입증되지 않으면 재검수 |
| 반영 뒤 응답 유실 | 대상 HEAD가 승인 커밋이고 브랜치·작업폴더가 일치하면 완료 복구 |
| 대상에 사용자 변경 발견 | 보존하고 `finalize_uncertain` 또는 사전 조건 오류 반환 |

명시적 중단은 `cancel_run`입니다. `cancelling`은 완료가 아니며, 실제 프로세스 종료 확인 전 자원 잠금을 해제하지 않습니다. macOS의 소유 프로세스 그룹, Windows의 `taskkill /T`로 OpenCode 하위 프로세스 종료를 처리합니다. 작업이 스스로 OS 서비스나 완전히 독립된 프로세스를 설치하는 동작은 허용된 작업 범위로 간주하지 않습니다.

## 모델·자원 점검

`doctor.connection.healthy`는 로컬 HTTP API와 모델 등록 상태를 뜻합니다. 공급자 원격 인증 확인을 위해 유료 모델 호출을 자동 발생시키지 않습니다. 실제 작업의 `401 Invalid API key`는 사용자 OpenCode 설정/인증에서 해결해야 합니다. 이 도구는 다른 공급자의 자격 증명을 탐색해 대체하지 않습니다.

자원 프로파일은 같은 서비스 전체에서 동일 키에 동일 정의를 요구합니다. probe를 실행하는 시점은 잠금 획득 뒤, 모델 호출 전입니다. project-bound 자원은 실제 worktree 경로를 realpath로 비교합니다. 프로파일은 외부 서버를 자동 시작하거나 Editor 프로젝트를 자동 전환하는 명령이 아닙니다.

기존 규칙/명세를 바꾸었다면 이전 해시의 실행을 조용히 갱신하지 않습니다. 현재 작업을 검토하고 새 실행을 계획하세요. 작업의 목표, 검증 명령과 승인 자체도 재현 가능한 기록의 일부입니다.

## 업데이트와 정리

설치본은 버전·내용 해시를 가진 디렉터리에 저장합니다. 과거 release와 현재 실행의 job/spec 파일은 업데이트가 덮어쓰지 않습니다. 새 플러그인은 새 Codex 대화에서 읽힙니다. 동일 프로토콜 서비스가 실행 중이면 계속 이용하고, 불일치하면 기존 release로 현재 작업을 마친 후 명시적으로 종료하고 업데이트합니다.

`cleanup`은 서비스가 만든 완료/취소 실행 worktree만 제거합니다. 적용된 사용자 브랜치와 원래 checkout은 제거하지 않습니다. 원본 로그에는 코드·모델 대화·도구 출력 등 프로젝트 정보가 있으므로 Git에 추가하거나 공유할 때 주의해야 합니다.

서비스를 제거할 때는 먼저 실행 상태를 확인하고 필요한 작업을 완료/취소한 뒤 `stop`을 호출합니다. `codex plugin remove codex-opencode@personal`로 플러그인을 제거할 수 있습니다. 데이터와 과거 설치본 삭제는 사용자 관리 대상입니다.
