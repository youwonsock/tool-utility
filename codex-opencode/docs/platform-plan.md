# 지시자·구현자 플랫폼 독립화 보완 계획

## 1. 목표와 유지할 워크플로우

Codex·OpenCode·Claude Code·Kilo를 각각 지시자와 구현자로 선택할 수 있게 한다. 같은 플랫폼끼리의 위임을 포함해 16개 조합을 지원한다.

지시자는 사용자가 대화 중인 에이전트로 유지한다. 지시자가 계획과 작업을 제출하고, 서비스가 구현자를 실행한다. 다음 흐름을 모든 플랫폼에서 공통으로 사용한다.

**계획 → 작업 제출 → 격리된 worktree에서 구현 → 검증 → 지시자 검수·수정 요청 → 승인된 커밋 통합 → 최종 검증·승인**

지시자는 공식 MCP를 지원하는 로컬 CLI·IDE·데스크톱에서 연결한다. 구현자는 CLI·SDK로 실행한다. 스케줄링, 상태 전환, 자원 잠금, Git 통합, 증거 수집은 기존 공통 코어가 담당한다.

## 2. 공통 인터페이스와 작업 설정

- 기존 12개 MCP 도구와 기존 입력 형식을 유지한다. 설명과 운영 지침에서 특정 플랫폼에 종속된 표현을 정리한다.
- `submit_tasks.worker`에 실행 기본값, 각 작업의 `worker`에 작업별 선택값을 추가한다. 선택값은 `{platform, model?, profile?}`이며 플랫폼은 `opencode`, `codex`, `claude-code`, `kilo`다.
- 작업의 `worker`가 있으면 실행 기본값 전체를 대체한다. 모델 형식은 OpenCode·Kilo의 경우 `{providerID, modelID}`, Codex·Claude Code의 경우 문자열로 구분한다.
- 선택값이 없는 기존 요청은 OpenCode로 처리한다. 기존 `task.model`은 계속 지원하며, 새로운 모델 선택과 충돌하거나 다른 플랫폼에 사용되면 입력 오류로 거부한다.
- `profile`은 프레임워크의 로컬 실행 설정 이름이다. 플랫폼·프로필 설정은 제출 전에 검증하고 작업에 고정한다. 기본 모델은 최초 실행 준비에서 네이티브 설정으로 확정한 뒤 수정 시도에도 유지한다. 지정 모델이 없으면 실패하며 다른 모델로 자동 전환하지 않는다.
- 기존 실행에 작업을 추가할 때 실행 기본값을 변경할 수 없다. 신규 작업은 기존 기본값이나 자체 선택값을 사용한다.
- `doctor`는 플랫폼별 버전·기능·연결 가능 여부를 반환하고, `get_run`은 선택한 플랫폼과 실제 실행 버전·모델을 표시한다. 인증 정보와 내부 연결 식별자는 공개 응답에서 제외한다.
- 기존 요청의 정규화와 요청 해시 계산을 유지한다. 생략된 `worker`의 기본값 해석은 요청 해시 계산 후 수행해 같은 요청 ID의 재전송을 보장한다.

공통 워크플로우는 `delegate-agents`로 제공하고, `delegate-opencode`는 OpenCode를 기본 구현자로 선택하는 호환 진입점으로 유지한다.

## 3. 플랫폼 어댑터와 실행·복구 규칙

`WorkerBackend`에 실행 준비, 세션 시작, 작업 전달, 관측, 입력 응답, 대조, 취소, 종료 확인을 정의한다. 플랫폼 어댑터는 네이티브 이벤트를 기존 워커 상태와 입력 요청으로 변환하며, 상태 전환 자체는 공통 lifecycle 모듈이 검증한다.

| 구현자 | 연동 방식과 초기 기준 |
|---|---|
| OpenCode | 기존 전용 HTTP 서버와 SDK 유지. CLI·SDK `1.18.30` |
| Codex | CLI `0.146.0`의 `app-server` STDIO |
| Claude Code | Agent SDK `0.3.296`과 해당 패키지에 포함된 네이티브 런타임 |
| Kilo | CLI·SDK `7.4.23`, 작업별 전용 HTTP 서버 |

Codex `app-server`는 실험 기능임을 지원 문서에 표시하고 고정 버전의 계약·연결 검사를 필수로 한다. [공식 문서](https://learn.chatgpt.com/docs/app-server)

- **전달과 복구:** 프로세스 실행, 세션 생성, 모델 요청, 입력 응답의 의도를 외부 호출 전에 저장한다. 네이티브 요청 ID가 있으면 함께 기록하고, 없으면 프레임워크 상관 ID와 관측 기록을 사용한다. 전달 여부가 불확실하면 조회와 증거 대조만 수행하며 자동 재전송하지 않는다. 네이티브 런타임의 자동 재개·재전송 기능도 비활성화한다.
- **완료와 종료:** 응답 종료와 미처리 도구·입력 요청이 없음을 확인한 뒤 구현 완료로 판단한다. 실행한 프로세스의 PID·생성 시각·부팅 식별자를 기록한다. 취소 응답이나 부모 프로세스 종료만으로 자원 잠금을 해제하지 않는다. Windows 하위 프로세스 종료 불확실성과 기존 `orphaned`, `stop_uncertain` 처리를 유지한다.
- **권한과 질문:** 기존 `permission`·`question` 형식으로 변환하고 지원 가능한 응답을 표시한다. `always`의 효력은 현재 시도에 한정하며 전역 설정에 저장하지 않는다. 전달이 불확실한 응답은 재전송하지 않고, 입력 대기 전 단계로 복귀한다.
- **정책 적용:** 선언된 MCP 자원만 노출하고 재귀 위임·네이티브 하위 에이전트·백그라운드 작업을 차단한다. 연결 설정은 내부 공통 형식으로 정규화해 플랫폼 설정으로 변환한다. 표현하거나 검증할 수 없는 연결은 제출 전에 거부한다. Claude는 도구 제한과 필수 `PreToolUse` 검사, 승인용 `canUseTool`을 구분해 사용한다. [Claude 권한 문서](https://code.claude.com/docs/en/agent-sdk/permissions)
- **설정과 인증:** 기존 네이티브 인증을 사용하며 인증 파일을 작업 디렉터리로 복사하지 않는다. 상속된 설정이 워커 정책을 완화하면 실행 전에 실패한다. Kilo는 공유 데몬을 재사용하지 않고 작업별 인증 정보를 사용하는 전용 서버를 실행한다. [Kilo 런타임 문서](https://kilo.ai/docs/contributing/architecture/cli-runtime)

선언된 검증 명령은 플랫폼 공통 실행기로 옮긴다. 기존 OpenCode `1.18.30`의 플랫폼별 셸 선택·명령 실행 규칙을 기준으로 호환성을 검증하고, 실제 셸·작업 디렉터리·환경 설정 식별자·종료 코드·로그를 기록한다.

검증 명령의 실행 의도와 프로세스도 저장한다. 결과가 불확실하면 `unknown`으로 남기고 자동 재실행하지 않는다. 구현자와 검증 프로세스의 종료가 확인될 때까지 잠금을 유지한다. 최종 검증은 모델 요청 없이 전용 worktree에서 실행하며, 기존 commit·revision·context·명령 일치 조건을 유지한다.

## 4. 호환성, 마이그레이션과 배포

- 기존 MCP 도구 계약과 내부 서비스 RPC 버전은 `1`로 유지한다. 저장 형식과 신규 워커 기록 형식은 각각 `2`로 분리한다. 저장 파일의 기존 `protocol` 필드에는 `2`를 기록해 구형 서비스가 새 기록을 잘못 읽지 못하게 한다.
- 서비스 health에 지원 플랫폼과 형식 버전을 추가한다. 신규 클라이언트는 이를 확인하고 기능이 없는 구형 서비스에 대해 `UPDATE_PENDING`을 반환한다.
- 마이그레이션은 별도 `migrate --dry-run`·`migrate --apply` 명령으로 제공한다. 설치나 서비스 시작 중 자동 실행하지 않는다.
- 적용 조건은 서비스와 모든 관련 프로세스의 종료 확인, 자원 잠금 없음, 미해결 요청·제출 준비·통합·finalize 의도 없음이다. 조건을 만족하면 대기 작업과 검수 중 작업도 이전할 수 있다. 불확실한 소유권이나 미해결 기록이 있으면 `UPDATE_PENDING`으로 중단한다.
- 저널 checksum과 snapshot을 대조한 상태를 기준으로 변환한다. 요청 ID·원본 요청 해시·저장 응답, revision, 승인, 검증 기록, 커밋, context와 artifact 해시는 보존한다. 기존 실행은 OpenCode로 표시하고 기존 워커 파일은 v1 읽기 경로로 보존한다.
- 서비스와 같은 소유권 잠금을 획득하고 변경 대상 전체를 백업한다. 임시 변환본을 검증한 뒤 단계 기록에 따라 적용한다. 중간 장애 시 서비스 실행을 차단하고, 다음 마이그레이션 명령이 적용을 이어가거나 백업으로 복구한다. 복구 과정에서 모델이나 검증 명령을 실행하지 않는다.
- 폴더명·플러그인 ID·기본 데이터 경로는 유지한다. 설치 산출물에는 외부 SDK 의존성과 Claude 네이티브 자산을 포함하고 내용 해시에 반영한다. 원본 폴더를 이동해도 실행할 수 있어야 한다.
- 네 플랫폼의 MCP·워크플로우 설정을 내보내는 기능을 제공한다. 설치본 활성화와 사용자 전역 설정 등록은 별도 명시적 작업으로 분리한다.

## 5. 구현 순서와 완료 기준

1. **계약과 회귀 테스트:** 기존 41개 테스트의 회귀 조건을 유지하고, 워커 선택·전달 불확실성·프로세스 종료·마이그레이션 테스트를 먼저 추가한다.
2. **공통 코어 분리:** 기존 OpenCode 동작을 어댑터로 이동하고 공통 검증 실행기와 실행 설정 고정을 도입한다.
3. **신규 어댑터:** Codex·Claude Code·Kilo를 추가하고 각 어댑터의 권한·질문·취소·재시작 계약을 검증한다.
4. **호환성과 배포:** 오프라인 마이그레이션, 독립 실행 가능한 설치 산출물, 지시자 설정 내보내기와 운영 문서를 완성한다.
5. **CI와 실제 연결 검사:** Node 22의 `macos-15`·`windows-latest`에서 `npm ci`, `npm run check`, 별도 모델 호출 없는 연결 검사를 실행한다. 관련 경로의 push·PR과 수동 실행을 지원한다.

| 대상 | 필수 확인 |
|---|---|
| 워크플로우 | 수정 직후·재시작 후 이전 결과 승인 차단, 새 시도 승인·통합, 최종 검증 연결 조건 |
| 복구와 취소 | 전달·응답 손실, 워커 호스트 종료, 취소 경합, 종료 불확실 시 잠금 유지와 추가 요청 없음 |
| 혼합 실행 | 서로 다른 구현자의 의존 작업, 동일 자원 경쟁, 작업별 설정과 수정 시도 설정 유지 |
| 제출·증거 | 부분 등록 방지와 제출 복구, tracked·untracked 거절 증거 유지 |
| 마이그레이션 | 기존 기록·요청 재전송, 단계별 장애와 재개, 손상·활성 프로세스 차단, 구형 서비스 접근 차단 |
| 연결·설치 | 네이티브 초기화·MCP 연결, 버전·정책 불일치, 원본 폴더 이동 후 실행 |

16개 조합은 **지시자 설정 4종과 모의 워커 4종의 MCP 계약 시나리오**로 검사한다. 실제 CLI·SDK 초기화와 MCP 연결 결과는 별도로 기록한다. IDE·데스크톱에는 공식 설정과 확인 절차를 제공하고, 실제 확인하지 않은 화면은 지원표에 미확인으로 표시한다.

기본 동시 실행 수 2, 작업 제한 60분, 수정 시도 제한 3은 유지한다. 실제 유료 모델 작업 검증, 클라우드 구현자, 설치본 활성화는 이번 완료 기준에서 제외한다. 기존 SDK 버전과 다른 폴더의 변경을 보존하며 새 상태 머신 의존성은 추가하지 않는다.
